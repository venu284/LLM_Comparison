## 1. How CodeRouterBench scored its tasks

The paper documents the scorer **per dimension, not per source**: the Eval column of Table 5
(arXiv 2606.22902v3, App. B.1).

| Dimension | Table 5 sources | Eval |
|---|---|---|
| Code Generation | HumanEval+, MBPP+, BigCodeBench | Exec |
| Algorithm Design | LiveCodeBench, BigCodeBench | Exec |
| Bug Fixing | DebugBench, SWE-bench Lite | Exec |
| Code Completion | CRUXEval, HumanEval+ variants | Exec |
| Data Science | DS-1000, BigCodeBench | Exec |
| Multi-Language | HumanEval-X, MultiPL-E | Exec |
| Code Refactoring | Bugs2Fix, CanItEdit | Proxy+ |
| Code Understanding | CodeXGLUE Summarization | Proxy+ |
| Test Generation | LiveCodeBench, HumanEval+ variants | Proxy+ |

The Table 5 caption defines the two values: "Exec = execution-based pass@1" and "Proxy+ = proxy
metric supplemented by LLM-as-Judge". §4.1 says "Seven dimensions use execution-based scoring". That
is the six Exec rows plus the OOD agentic dimension ("Sandbox").

What the paper does not give:
- a scorer per source;
- the pass@1 sample count;
- a partial-credit rule;
- a definition of the proxy metric;
- the `_sup` tasks, which it never mentions.

The ACRouter code repository (`github.com/LanceZPF/agent-as-a-router`) returned 404. The Route
Anything repository (`@e137f3f`) documents no per-family scorer.

- **Undocumented families:** none is labelled `undocumented`, because every family falls under its
  dimension's Table 5 rule. Two families have no source rule (he_testgen, mbpp_testgen); both are
  ineligible under the CodeRouterBench rule anyway. Three rulings rest on that dimension-level reading
  or on a single source statement, and the user decides them:
  - `bcb_completion` (89 tasks) and `mbpp_completion` (124 tasks) are eligible only through the
    Code Completion rule. Table 5 does not list their sources under that row.
  - `debugbench` and `debugbench_sup` (1,040 tasks) are ineligible on one footnote: the tests need
    a LeetCode account. Yet CodeRouterBench calls the dimension "pass@1 in sandboxed environments".
- **Partial credit:** "unstated" for every ID family. The paper gives no sample count or per-task
  aggregation. Route Anything calls the released score's mechanism a "pass fraction"
  (X8 README); that is a third-party statement and is recorded only.
- **Success:** `success(score)` is `score >= SUCCESS_SCORE` (1.0), whatever the partial credit.

## 4. Cross-checks (report-only, after the freeze)

| Family | Eligible | Distinct released scores | Cells at 1.0 / cells | Flag |
|---|---|---|---|---|
| hex_cpp, hex_go, hex_java, hex_js | yes | 999–1,135 | 1, 0, 16, 0 of 1,312 each | **The data contradict the rule.** Pass@1 over n samples takes multiples of 1/n, and 999–1,135 distinct values in 1,312 cells would need n in the hundreds for every cell. Almost no successes under S0.1 |
| multiple_rs, multiple_ts | yes | 1 | 0 / 1,248; 0 / 1,080 | **Every released score is 0** |
| swebench | yes | 1 | 0 / 568 | **Every released score is 0** |
| cruxeval, mbpp_completion, hex_python | yes | 3 {0, 0.8, 1} | 2,277 / 6,400; 717 / 992; 1,235 / 1,312 | Fractional scores, rule unstated |
| lcb | yes | 10 | 2,657 / 8,000 | Fractional scores (129 tasks), rule unstated |
| debugbench | no | 3,351 | 952 / 7,432 | Continuous under an Exec rule (the same contradiction) |
| debugbench_sup, mbpp_testgen | no | 1 | 0 | Every released score is 0 |

- **Route Anything `runnable = false` share:**
  - hex_cpp, hex_go, hex_java and hex_js: 100%. Their sandbox has no toolchain for those languages.
  - he_testgen and lcb_testgen: 100%.
  - BigCodeBench families: 4–14%, because of missing libraries.
  - All other covered families: 0%.
  - Not covered at all: multiple_rs, multiple_ts, swebench, debugbench, bugs2fix, codexglue,
    canitedit and mbpp_testgen.
- **Scores in [1 − 1e-9, 1.0):** none in any family.
- **A shared {0, 0.8, 1} pattern:** cruxeval, mbpp_completion and hex_python take exactly the
  values {0, 0.8, 1}. That looks like a grader value, not the result of sampling.
- **Citation provenance:**
  - Paper quotes come from arXiv HTML read through a fetch tool, with partial verbatim coverage per
    paper. Only quotes from verbatim text were used.
  - Exception: the swebench note's "FAIL_TO_PASS / PASS_TO_PASS" wording comes from a part of the
    SWE-bench paper the tool only summarised.
  - Dataset-card quotes come from the pinned local cards in
    `external/route-anything-data/provenance/`.

No rule was changed to fit these data (R16).
