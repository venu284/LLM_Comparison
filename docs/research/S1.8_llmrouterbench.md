# S1.8 — LLMRouterBench: pinned loader and descriptive profile

_2026-11-21 · branch `s1-8-llmrouterbench` · plan §4 S1.8 · brief `.claude/handover/2026-11-21-s1-8-llmrouterbench.md`_

S1.8 delivers a pinned loader and a descriptive profile of LLMRouterBench's code subsets. It
produces no splits, no audit labels and no claim numbers. No oracle, DimensionBest or routing gain
is computed. The numbers come from `router/experiments/out/s1_8_profile.json` (rebuilt by
`router/experiments/s1_8_profile.py`, byte for byte).

How the archive is handled (`scripts/fetch_data.py`, `ARCHIVES`):
- The tarball is untrusted data. It is downloaded into a fresh, empty temporary directory outside
  `external/`, checked against the pinned sha256, extracted and deleted.
- Every member is checked before anything is written. A member is rejected if it has an absolute
  path, has a `..` component, or is anything other than a regular file or a directory (symlinks,
  hard links and devices are all rejected). Allowlisted members also pass Python's `data` filter.
- Files are staged in `.part/` and moved into place only when the whole archive has been read.
- The tarball's hash is in the `# archive:` header line of `external/CHECKSUMS`. The 95 extracted
  files are body lines, so `shasum -a 256 -c CHECKSUMS` still works.
- `--write-new-checksums` adds pins without touching existing lines: 102 lines were added and 0
  changed. `--verify-only` verifies 304 files.

## 3. Loader (`router/data/llmrouterbench.py`)

`load()` returns the following:
- `long`, in `schema.LONG_COLUMNS` form. It holds only cells a model ran: ragged across subsets
  and never zero-filled. It has 69,123 cells, of which 444 are unavailable (443
  `missing_token_record`, 1 `null_score`).
- `matrices`: one dense `OutcomeMatrix` per subset, because every model file in a subset covers
  every task.
- `tasks`: the text (`origin_query`, `prompt`) and the source key.
- `cells`: per-cell fields the schema has no column for (recorded cost, output length, flags).
- `files`, and `cost_flags`.

Column mapping:
- `family` is the subset, prefixed (`lrb_humaneval`, `lrb_mbpp`, `lrb_livecodebench`,
  `lrb_swebench_verified`) because CodeRouterBench also has `humaneval` and `mbpp`.
- `dimension` is `code`, `problem_id` and `split` are null, and `score_type` and `eligible` come
  from `RULES`.

Choices made:
- **Model axis.** The `model_name` field is used, not the directory name: `swe-bench/verified/gpt-5/`
  holds a `gpt-5-medium` file named `gpt-5`, and `swe-bench/verified/qwen3-235b-a22b-thinking/`
  holds `qwen3-235b-a22b-thinking-2507`.
- **The `openrouter` files** (1,055 LCB and 500 SWE cells) are OpenRouter's own router,
  `openroute/auto`, which is a routing baseline in the paper (App. B.3), not a model. They are kept
  off the model axis and counted separately.
- **Possible duplicate models are kept separate and flagged:**
  - `intern-s1` and `intern-s1-new`;
  - `qwen3-235b-a22b-thinking` and `qwen3-235b-a22b-thinking-2507`;
  - also `qwen3-235b-a22b-no-thinking`;
  - `gpt-5` on SWE comes from a file named `…gpt-5-medium…` (a reasoning-effort setting) and is
    merged by `model_name` with LCB's `gpt-5`. It may be a different configuration, and it is one
    of the 13 models LCB and SWE share.
- **Null score.** The one null score (internlm3-8b-instruct, MBPP, index 665, raw output
  "Processing failed: source code string cannot contain null bytes") is unavailable, with the new
  reason `null_score` (S0.11).
  - `schema.py` gains `NULL_SCORE` and `ALL_UNAVAILABLE_REASONS`.
  - `UNAVAILABLE_REASONS` is unchanged, because `audit.build_artefacts` writes every reason in it
    into the frozen `artefacts.yaml`.
- **Zero-token records.** A cell with zero input tokens, zero output tokens and zero cost is
  unavailable, with the existing reason `missing_token_record`. CLAIMS S0.11 already makes this
  pattern unavailable for CodeRouterBench ("the zero-score, zero-cost Qwen3-Max rows mark the
  model as unavailable"). The test reads tokens and cost only, never the score (R16). This covers
  443 cells (LCB 355, SWE 88), all with a released score of 0, which is kept as released.
  - Not covered, and kept as available failures: the 12 zero-cost SWE cells that have tokens, and
    the 669 empty outputs. This matches the CodeRouterBench checkpoint 1 decision on empty
    responses.
- **Zero-cost models** (every recorded cost in the subset is 0) keep their scores and get
  `cost_usd = NaN`. They are excluded from cost metrics and not priced (plan; S0.2 pricing is the
  user's later decision).

### Source keys

The keys are in the `splits.source_key` namespace. No record carries a source id, except
SWE-bench's `instance_id`. `index` is a 1-based list position (`runner.py` l.280) and is never
used as an id.

| Subset | Rule | Mapped |
|---|---|---|
| HumanEval | `origin_query` equals the `prompt` of exactly one task in `openai_humaneval` | 164 / 164 unique. Cross-check: `index` = N + 1 for all 164 |
| MBPP | The whitespace-collapsed record prompt equals LLMRouterBench's MBPP template, filled with one task's `text` and `test_list` | 974 / 974 unique. The text alone is shared by four pairs of MBPP tasks (8 records), and only the tests separate them. With exact (not whitespace-collapsed) matching, 947 map |
| LiveCodeBench | `origin_query` equals one `question_content` in the pinned `livecodebench` extract (v1–v6) | 1,055 / 1,055 unique |
| SWE-bench Verified | The record's `instance_id`, checked against `swebench_verified_ids` | 500 / 500 |

### Models shared with CodeRouterBench

There are no exact name matches with `prices.py`'s CodeRouterBench models. LLMRouterBench has
earlier versions of the same vendors' models (claude-sonnet-4, gpt-5, glm-4.6, kimi-k2-0905 and
others). Price agreement therefore cannot be checked by name.

Fitting recorded cost = a × input + b × output per model reproduces each cell exactly (relative
residual 0) for most models. Examples:
- claude-sonnet-4: $3 / $15 per million tokens;
- claude-opus-4.1: $15 / $75;
- gpt-5 and gpt-5-chat: $1.25 / $10;
- the small models: cents per million.

Five models have per-cell variation: gemini-2.5-flash, gemini-2.5-pro, deepseek-v3.1-terminus,
qwen3-235b-a22b-2507 and -thinking-2507. These are presumably OpenRouter provider-dependent prices
(paper App. B.1). The fit is in `implied_prices`.

## 5. What making LLMRouterBench a primary corpus would still need

1. **Eligibility review.** The SWE-bench scorer is undocumented, and HumanEval and MBPP show the
   tests in the prompt. Under R1 the verifier's and grader's tests must be disjoint, so with the
   tests shown in the prompt there is no hidden test set for these two subsets.
2. **Task text** for the router field, and a decision on whether LCB starter code is part of it.
3. **Problem ids and splits across both corpora.** Every CRB HumanEval, MBPP and LCB problem is
   shared, so S1.6's problem grouping must be extended over both corpora before either is split.
4. **An artefact audit (S1.7 type):**
   - cells consistent with failed requests scored 0: the 443 zero-token cells (unavailable here),
     the 12 zero-cost SWE cells with tokens, and the 669 empty outputs;
   - the MiMo token cap;
   - the LCB private-test fallback;
   - the possible duplicate or differently configured models (`intern-s1-new`, the
     `qwen3-235b-a22b-thinking` variants, `gpt-5-medium`).
5. **Pricing** for the nine zero-cost models (S0.2, tokens × published price), and a rule for the
   partial-zero-cost cells.
